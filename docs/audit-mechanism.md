# Agent Audit Mechanism

When agent workflows deal with high-value actions, transparency, debugging, and persistence become extremely critical. Wayang AI provides a built-in **Agent Audit Mechanism** allowing system operators and developers to review the thought processes, plan steps, and execution checkpoints of active agents.

---

## 📝 The `AgentAuditService`

Wayang exposes an SPI `AgentAuditService` in the `wayang-agent-core` module that persists different types of execution steps (referred to as `AgentArtifact`s) during a lifecycle run. Types of artifacts generally include:
- `plan`: Detailed multi-step planning generated by Planner Skills.
- `task`: Distinct broken-down objective checkpoints.
- `implementation`: Code edits, API execution requests, or intermediate data.
- `walkthrough`: Summary of all actions completed by the end of a session.

### Strategy Configuration

Wayang offers two built-in implementations of this service, entirely configurable via your application environment properties.

```properties
# Valid strategies: 'file' or 'pgsql'
wayang.agent.audit.strategy=pgsql
```

### 1. File Strategy (`file` / `local`)
Stores artifacts as flattened Markdown (`.md`) files on the filesystem. Ideal for rapid local development, human readability, and manual Git tracking.

**Default Directory**: `/tmp/wayang/audit/`
*(Changeable via `wayang.agent.audit.file.directory=...`)*

Produces structured documents with YAML frontmatter:
```markdown
---
ID: 1efdca01-8b01...
RunID: cf41b654...
Type: plan
Date: 2026-03-09T00:00:00Z
---

# Agent Execution Plan
1. Retrieve logs
2. Fix standard error
...
```

### 2. Relational Database Strategy (`pgsql` / `database` / `db`)
For production telemetry and cross-node distributed resilience, the platform leverages `quarkus-hibernate-reactive-panache` linked to PostgreSQL.

- **Non-blocking**: Uses fully reactive database connections (`quarkus-reactive-pg-client`).
- **Queryable**: Agents and dashboards can instantly recover old run-states across a cluster by `tenantId` and `runId`.
- **Entity**: Data is mapped to the `agent_audit_records` Postgres table.
